## Project

Veilance is a Stellar + ZK hackathon project. It verifies Noir (UltraHonk) zero-knowledge proofs on-chain via Soroban smart contracts deployed to Stellar.

## Toolchain Versions (pinned — do not upgrade without confirming)

- **Noir**: 1.0.0-beta.9
- **Barretenberg (bb)**: 0.87.0
- **Rust target**: `wasm32v1-none`
- **Stellar CLI**: ≥ 3.2.0
- **Soroban SDK**: pinned in each `Cargo.toml` to a specific commit
- Circuits must be compiled with `--oracle_hash keccak`

## Protocol Status (verified 2026-06-29)

- Testnet: Protocol 27 | Mainnet: Protocol 26
- **BN254** host functions (`g1_add`, `g1_mul`, `pairing_check` + MSM/scalar field from CAP-80) → live on mainnet (P26)
- **Poseidon/Poseidon2** (CAP-75) → live on mainnet (P25)
- Poseidon requires the `hazmat-crypto` feature flag in `Cargo.toml` — this is an SDK gate, not a network gate
- The ZK skill doc references "CAP-0074/0075 as proposals" — those shipped as CAP-75 (Poseidon) and CAP-80 (BN254 extended). Ignore the skill doc's framing of them as unshipped.

## Common Commands

```bash
# Build circuits (must run before cargo test)
just build-circuits

# Build Soroban contract WASM
just build-contract

# Run all tests (requires circuit artifacts)
cargo test --workspace --all-features --release

# Run a single test
cargo test --release <test_name>

# Full end-to-end: start local network → fund → deploy → verify
just e2e

# Deploy to testnet and submit proof
just testnet

# Deploy contract manually
just deploy

# Invoke verify_proof on a deployed contract
just verify <CONTRACT_ID>
```

## Soroban Contract Pattern

All verifier contracts follow the `indextree/ultrahonk_soroban_contract` pattern:

**`__constructor(env, vk_bytes)`** — validates and stores VK in instance storage at deploy time. Rejects re-initialization.

**`verify_proof(env, public_inputs, proof_bytes)`** — loads VK from storage, instantiates `UltraHonkVerifier`, calls `verifier.verify(&env, &proof_bytes, &public_inputs)`.

**`vk_bytes(env)`** — returns stored VK for auditability.

### Error Taxonomy (use exactly these variants)

```rust
VkInvalidLength = 1        // wrong byte count
VkInvalidParameters = 2    // out-of-range structural params in VK header
ProofParseError = 3        // proof size != PROOF_BYTES constant
VerificationFailed = 4     // cryptographic check failed
VkNotSet = 5               // constructor never called
AlreadyInitialized = 6     // constructor called twice
```

### Key Dependency

```toml
ultrahonk_soroban_verifier = { path = "../crates/ultrahonk-soroban-verifier" }
# or via git — check crates/Cargo.toml for the pinned source
```

## Test Pattern

```rust
const CONTRACT_WASM: &[u8] =
    include_bytes!("../target/wasm32v1-none/release/<contract>.wasm");

// Embed circuit artifacts — generated by just build-circuits
let vk_bytes_raw = include_bytes!("circuit/target/vk");
let proof_bin    = include_bytes!("circuit/target/proof");
let pub_inputs   = include_bytes!("circuit/target/public_inputs");

let env = Env::default();
env.budget().reset_unlimited(); // required in test env
let contract_id = env.register(CONTRACT_WASM, (Bytes::from_slice(&env, vk_bytes_raw),));
let client = Client::new(&env, &contract_id);
client.verify_proof(&Bytes::from_slice(&env, pub_inputs), &Bytes::from_slice(&env, proof_bin));
```

Always include a negative test (invalid proof → expect `VerificationFailed`).

## Architecture

```
smoke-test/
├── circuits/               # Noir source (.nr) + compiled artifacts (target/vk, target/proof, target/public_inputs)
├── contracts/              # Soroban contract crate(s)
│   └── src/lib.rs          # Contract: __constructor + verify_proof + vk_bytes
├── crates/                 # Shared Rust crates (ultrahonk-soroban-verifier, test-utils)
├── tests/                  # Integration tests (embed artifacts via include_bytes!)
├── scripts/                # JS/TS helpers for on-chain invocation
├── Cargo.toml              # Workspace root
└── justfile                # All build/deploy/test commands
```

The verifier crate (`ultrahonk-soroban-verifier`) wraps the Barretenberg UltraHonk verifier as a `no_std` Rust library usable inside Soroban WASM. The contract crate is a thin wrapper that handles storage and error mapping.

## Trust Model

Contracts store an immutable VK set at deploy time — no admin key, no upgrade path for the VK. Callers must independently verify the stored VK against a known-good circuit before trusting proofs. The contract address alone is not a trust anchor.
